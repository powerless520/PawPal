### T0.1 — TTS 真声音（macOS 优先）

详见 R7 文档 7.1。**1 天**。

### T0.2 — 同人图导出 PNG

详见 R7 文档 7.2。**0.5 天**。  
最强拉新方式（小红书 / 朋友圈分享）。

### T0.3 — 互动彩蛋

详见 R7 文档 7.3。**1 天**。  
8 个**纯本地**彩蛋，零 AI 依赖。

### T0.4 — 主题系统（Skin / Theme）

**当前状态**：styles.css 是单一文件，所有颜色 / 字体 / 圆角硬编码在 CSS rules 里。**没有"换肤"概念**。

**问题**：如果用户想"深色模式" / "复古风" / "高对比度" —— **做不到**。

**方案**：
- 抽出 CSS 变量到 `.theme-{name}` 类（不是 `:root`）
- theme 由 React 状态控制
- Settings 加"主题"下拉：`default` / `midnight` / `sakura` / `paperwhite`
- 主题文件：`src/renderer/src/themes/default.css` / `midnight.css` ...

**实现要点**：
- 现有 styles.css 已经是 design token 风格（变量都在 `:root`），**几乎不用改**
- 只是把 `:root` 拆到 `.theme-default` 里，新增 `.theme-midnight` 覆写
- 一个 `useTheme()` hook 根据 settings.theme 切 class

**工作量**：半天（不需要新增代码，主要重构 CSS）。**视觉回报高**。

### T0.5 — 设置面板"导航/搜索"

**当前问题**：14 个分组纵向排列，**没有目录、没有搜索**。用户找一个"AI 提示词"选项要往下滚 4 屏。

**方案**：
- 左侧 sidebar（240px 宽）：分组列表
- 右侧 main：当前分组内容
- 顶部搜索框：跨分组筛选 Row（"AI"显示所有 AI 相关 Row）
- macOS native sidebar style（`role="navigation"` 配合 `list-style`）

**工作量**：1 天。**从此设置面板从"长表"变"应用"**。

### T0.6 — 表情包 / 贴纸

**当前问题**：宠物说的气泡文字是**硬编码的中文 / 英文**。

**方案**：
- 把气泡池提到 `shared/stickers.ts` 作为可加载数据
- 加 `src/renderer/stickers/` 放更多贴纸
- 支持"用户上传贴纸"（zip 包含 png + json 元数据）
- AI 用贴纸 ID 而不是纯文本

**工作量**：1-2 天。**让气泡更有"个性"**。

### T0.7 — 宠物"皮肤包"系统（`.petpack`）

**当前问题**：内置宠物在源码里，**用户不能加自己的角色**。

**方案**：
- `.petpack` = 包含 `manifest.json` + `pet_assets/<id>/<state>/<file>.gif` 的 zip
- "导入皮肤包"按钮 → 解压到 userData/pet_packs/ → 刷新 settings
- 皮肤包在 setting 下拉里显示 "🐉 龙龙 (by xxx)"  
- 用户可以一键切换、删除、导出

**工作量**：1.5 天。**用户创造内容（UGC）** 的入口。

### T0.8 — 桌面挂件（macOS Widget）

**当前问题**：用户每天开 app 看 pet 的次数 = 0（除非主动想起来）。

**方案**：
- macOS 14+ 的 `WidgetKit`，`WidgetExtension`
- 2x2 桌面挂件：宠物头像 + mood emoji + 今日喝水 N 次
- 点击挂件 → 唤起主 app

**工作量**：1-2 天（需要 Swift 桥接，**macOS only**）。**提升日常触点 ×10**。

### T0.9 — 跨设备同步（iCloud Drive / Dropbox）

**当前问题**：换电脑就丢所有数据。

**方案**：
- 用户设置里选"启用 iCloud 同步"（或 Dropbox / OneDrive）
- 启动时检测 `~/Library/Mobile Documents/com~apple~CloudDocs/PawPal/`
- 双向 sync：本地 store.json + 远端文件，存在冲突时以 mtime 新的为准
- 实际是**单向写远端 + 启动时拉一次**（避免实现真正的 CRDT）

**工作量**：1 天。**用户信任基础**。

### T0.10 — "宠物同人图"模板化

详见 R7 文档 T0.2。**0.5-1 天**。

### T0.11 — 协作 / 共享（局域网 mDNS）

**当前问题**：单机孤岛。

**方案**：
- 启动时广播 mDNS 服务（`_pawpal._tcp.local`）
- 同一 WiFi 下两台 Mac 自动发现
- 看到朋友的 pet 时发气泡"你朋友来啦~"
- 朋友侧也能看到你的 pet 走过屏幕（可关）

**工作量**：2-3 天。**网络效应**。

## Tier 1 — 把现有功能"做完整"

> 已有数据结构，但**没接上**或者**体验不到位**的。

### T1.1 — 翻页日记本

**当前**：日记是 flat list，每条独立卡片。

**改进**：
- 加一个"日记本"按钮在 chat 窗口或 settings
- 切换到"书本模式" → 翻页动画（CSS 3D `transform: rotateY()`）
- 每天一页，左页是前一天日记，右页是今天
- 视觉包装：纸纹理 + 翻页阴影

**工作量**：1 天（纯 CSS + React transition）。

### T1.2 — 宠物"年龄"分阶段

**当前**：pet 永远看起来一样。

**改进**：
- `petGrowth.bornAt` 已经记录
- 引入 `petAgeStage: 'baby' | 'teen' | 'adult'`
- 阶段阈值：0-7 天 baby，8-30 teen，30+ adult
- manifest 升级：每个 pet **3 套 asset**（按 stage 分）
- renderer 根据 stage 选对应目录

**工作量**：1-2 天。**让用户感觉宠物真的在长大**。

### T1.3 — 节日倒计时

**当前**：节日才自动换装扮，**用户不知道下一个节日什么时候到**。

**改进**：
- 设置里加"下一个节日：圣诞（还有 84 天）"
- 主窗口上偶尔弹气泡"还有 X 天到 Y 哦~"
- 节日当天第一条气泡带"✨ 今天是 Z 哦！" + 立即触发节日装扮

**工作量**：0.5 天。

### T1.4 — 声音版日记

**当前**：日记是文字。

**改进**：
- 日记条目旁边加 🔊 按钮
- 点击 → 用 `say`（macOS）/`SAPI`（Win）/`espeak`（Lin）读出
- 设置加"播报声音"开关

**工作量**：0.5 天（macOS 0.5 小时）。

### T1.5 — 宠物"看时间"行为

**当前**：pet 不知道时间。

**改进**：
- 每 30-60 分钟，pet 会"看表" + 气泡"已经下午 3 点了~"
- 周末、节日、特殊时间点有专属气泡
- "Friday 5pm" 触发"周五啦！下班！"

**工作量**：1 天。

### T1.6 — "今日一句"开机问候

**当前**：启动后 pet 沉默。

**改进**：
- 启动后 3-5 秒，pet 说一句话
- 看时间 / 季节 / 上次 mood 决定内容
- 早上 / 中午 / 晚上 / 深夜不同话术

**工作量**：1.5 天。

### T1.7 — 观察者模式

**当前**：宠物**永远在主动搭话**（可能打扰工作）。

**改进**：
- 设置加"观察者模式"开关
- 开启后：宠物不主动说话、不游走、不动
- 只在你点击/拖动/切换 pet 时响应
- 给"想静静"的人用

**工作量**：0.5 天。

### T1.8 — 宠物"学习用户习惯"

**当前**：pet 行为纯时间驱动。

**改进**：
- 记：你几点开始工作、平均工作多久、每天开 app 几次、最爱哪个 action
- pet 偶尔引用："你今天已经工作 4 小时了~"

**工作量**：1-2 天。

## Tier 3 — 架构 / 工程质量

### T3.1 — ESLint + Prettier

2 小时。**最该做的**（再不做 commit 风格就开始乱）。

### T3.2 — e2e 测试（Playwright）

1 天。当前只有纯逻辑测试，没有"打开 app 能不能跑"测试。

### T3.3 — CI 多平台 build

1 小时。当前只在 ubuntu build，没出 mac/win artifact。

### T3.4 — 抽 PetWindow 抽象层（真多窗口基础）

1-2 天。之前评估过 1-2 周的"真多窗口"——但只做**抽象**1-2 天，把 `petWindow` 变成 `Map<PetId, BrowserWindow>` 的脚手架，roster 真实支持多 pet 窗口在以后 commit 做。

### T3.5 — 主进程模块化

`main.ts` 已经 2390 行了，**单文件上限**。建议拆：
- `main/petWindow.ts`（窗口管理）
- `main/scheduler.ts`（提醒 / 游走 / 搭话 / 心情所有 timer）
- `main/stats.ts`（统计 + 日记 + 成长 + 心情历史）
- `main/roster.ts`（多宠物档案）

**工作量**：1 天（re-org 不改行为），未来加速明显。

### T3.6 — 升级到 Electron 32+

升级 electron / electron-vite / electron-builder，**可能 break**（API 变化），需要 1-2 天测试。

### T3.7 — Rust 化部分主进程逻辑

把 statistics 累加、diary 写入这些**热路径**用 Rust 写（通过 napi-rs），快 5-10x。**2-3 天**，纯优化不推荐现在做。

### T3.8 — 设置数据 schema 校验

Settings 从 electron-store 读出来时，**没有任何 schema 校验**。老的 store 升级字段缺失会 silent 失败。加 zod-style 校验：半天。

### T3.9 — 错误日志 / Sentry 集成（本地）

`console.error` 全无结构化。加个简单 `logger.ts` 把错误按 level 输出到 `~/Library/Logs/PawPal/...log`。半天。

### T3.10 — 启动时间优化

现在启动到窗口可见大概 1-2 秒。可以用 vite-plugin-fast-entry / 拆分 main bundle 优化。1 天。
